Response times

  • Errors that stop the trash from keeping or restoring items: we aim to reply within 2 business days.
  • Other requests: we aim to reply within 5 business days.

These times apply during Monday to Friday, 09:00 to 17:00 Central European Time.

What to include

A good request lets us answer without asking questions first.

  • Your Statamic and PHP versions, and the addon version (php please support:details prints them all).
  • Whether the site stores content in flat files or with the Eloquent driver, and which disk the trash uses.
  • The id of the item, from the trash or from php please trash:list, if the problem is with one item.
  • What you expected to happen, and what happened instead. A screenshot helps.
  • When it happened, with your time zone.

Please do not send passwords or confidential content. If we need an example, we will ask for it.

Common questions

A deleted item is not in the trash.

Check that its type is ticked in the settings and that its collection, taxonomy, container or form is not in the exclude list. Assets larger than the largest asset setting keep only their details. Files deleted outside Statamic, on disk or by git, are never captured.

Restore says the slug was taken.

Another entry uses the slug now, so the restored entry got a number at the end, such as about-us-2. Change it on the entry page if you want.

Restore says the collection no longer exists.

The collection was deleted, and its entries were kept. Create the collection again with the same handle, then restore the entries.

An editor cannot see the trash or restore.

They need View the trash, and to restore also Restore items plus the right to create that kind of item. On Statamic Core there are no roles, so only the super admin uses the trash.

Old items are not removed.

They are removed by Laravel's scheduler once a day, and whenever the trash is opened. php please trash:purge removes them now.

Can a restored user sign in?

Not until they set a new password, because passwords are never kept. Send a password reset from their user page.

Security issues

If you believe you have found a vulnerability, do not post it publicly. Write to support@karelialabs.atlassian.net instead. The security page says what to include.
