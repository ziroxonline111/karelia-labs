Security and data

Brandwright runs entirely on Atlassian. Pages are read through the Confluence API as the person who exports, made into documents inside Forge, and kept for download for three days. It makes no calls to outside servers.

Built only on Atlassian Forge

Brandwright is built only on Atlassian Forge. Its manifest allows no outbound network access and has no remotes, no web triggers and no Connect modules. Its eligibility for Atlassian's Runs on Atlassian program has not been confirmed yet.

Where your data goes

Nowhere outside Atlassian. The app declares no outbound network access, no remotes, no web triggers, no external backend, no analytics, no email and no third-party service, and it requests no content or external permissions, so the interface runs under Forge's default content security policy (no inline script, no eval, no external hosts). A browser test loads the interface under that policy and fails on any violation. Pages are read by Forge functions through the Confluence REST API, made into Word and PDF files there, kept in the app's storage for download for three days and, only if the user asks, attached to the page.

Forge storage follows the data residency of the host product (your Confluence or Jira site). Atlassian runs Forge functions on its own infrastructure and aims to run them in the same region.

What is stored

The app stores data in Forge hosted key-value storage only (no SQL, no object store, no custom entities). Page content is read in memory while an export runs; only the finished files are kept.

Personal data

Atlassian account ids of the people who start exports and upload templates. The app stores no names or email addresses. A scheduled function runs every day and reports the stored account ids to Atlassian's personal data reporting API once every seven days. For accounts reported as closed, the app erases their export jobs and files and removes their ids from templates. Page content that passes through the app may contain personal data, for example the name that the {author} tag prints, and is kept only as the table above says.

Permissions

Every permission the app requests, and why. The scopes are granular unless the table says otherwise.

ScopeWhy the app needs it
storage:app Forge storage on your site for the template library, export jobs and their files
read:page:confluence Read the page that is exported: its title, its body, and the version and date of the last change
read:hierarchical-content:confluence List the child pages of the exported page, for the page tree option
read:space:confluence Read the name of the space, for the {space} tag
read:content-details:confluence Read the name of the person who created the page, for the {author} tag
read:attachment:confluence List the attachments of a page and download the PNG and JPEG pictures that the page shows, so that they appear in the document
write:confluence-file Classic scope. Attach the exported Word or PDF file to the page, only when the user chooses to. The upload of an attachment needs this scope
report:personal-data Report stored account ids to Atlassian's personal data reporting API

Offline user impersonation (allowImpersonation) is enabled on the six Confluence scopes, because an export runs in the background after the person may have closed the dialog. It acts as the person who started the export, so Confluence's own permissions decide what is read and where files can be attached. There are no delete scopes, no user scopes and no admin scopes.

Access control

Every Confluence request is made with the identity of the person who started the export. A page that person may not see is not exported. A person sees only their own exports, and can have up to three running at a time. Templates are managed on the app's page in the Confluence settings, which has a resolver of its own that the export dialog cannot call. The licence is checked on the server for every request from the interface and fails closed in production.

Untrusted input

Word templates and page content are untrusted input. Uploaded files are opened by a careful reader that refuses macro-enabled files, old .doc files, password-protected files, zip bombs and files over 10 MB, and every template is checked when it is uploaded. Tags are matched by name against a fixed list: there is no expression language, and no code from a template is ever run. Automated tests cover hostile templates and page content.

Dependencies

The bundled open source packages (among them docxtemplater, pizzip, pdf-lib, fontkit, xmldom and Preact) are all under permissive licenses, and the build check fails if a package with another license appears. The Roboto font (Apache License 2.0) is embedded for PDF output.

Logging

Error class and message only. Page content, template content and file names are never logged.

Encryption

Data in transit and at rest is protected by the Atlassian Forge platform. The app has no database or storage outside Forge.

Sub-processors

None besides Atlassian.

AI and language models

None. The app does not use Forge LLM and sends no content to any model.

Vulnerabilities and incidents

We fix vulnerabilities within the windows Atlassian requires of Marketplace apps (critical: 10 days, high: 4 weeks, medium: 12 weeks, low: 25 weeks) and tell Atlassian about security incidents within 48 hours. Dependencies are checked for known vulnerabilities before each release.

Report a vulnerability to support@karelialabs.com. Please include what you found, how to reproduce it and which app and version are affected, and give us a reasonable time to fix it before you publish details.

Deleting data

Templates are deleted on the settings page. Everything else expires by itself (see the table). Uninstalling the app removes it from your site, and Atlassian then deletes its stored data under its Forge data retention rules. Files attached to pages stay with your pages, because they belong to your Confluence.
