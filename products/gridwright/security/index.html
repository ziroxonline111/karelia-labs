Security and data

Gridwright requests no permissions and stores nothing of its own. A table is the value of its Jira field, kept by Jira, and the app makes no calls to outside servers.

Built only on Atlassian Forge

Gridwright is built only on Atlassian Forge. Its manifest allows no outbound network access and has no remotes, no web triggers and no Connect modules. Its eligibility for Atlassian's Runs on Atlassian program has not been confirmed yet.

Where your data goes

Nowhere outside Atlassian. The app declares no outbound network access, no remotes, no web triggers, no external backend, no analytics, no email and no third-party service. The rows of a table are the value of the field, which Jira stores with the issue. The columns are the configuration of the field context, which Jira stores with the field. Jira hands both to the app when a person views or edits the field.

The app has no storage of its own, so tables follow the data residency of your Jira site. Atlassian runs Forge functions on its own infrastructure and aims to run them in the same region.

What is stored

The app uses no Forge storage of any kind: no key-value store, no SQL, no entities, no object store. Table rows are stored by Jira as the value of the field, and the column setup is stored by Jira as the configuration of the field context. Calculated cells are saved with the rows, so that Jira's search and the summary can use them, and are worked out again from the column setup whenever the table is shown or saved.

Personal data

None is stored by the app. It requests no account ids, names, email addresses or profile data, and this version has no user picker column. A person may type personal data into a cell; it is then part of the issue and handled by Jira like any other field value. Because the app stores no personal data, it has nothing to report to Atlassian's personal data reporting API and requests no scope for it.

Permissions

Gridwright requests no scopes at all. The table is the value of its own field and the columns are the configuration of its field context. Jira hands both to the app when a person views or edits the field, so the app calls no Jira API. There is no write scope, no impersonation and no app-level access.

Access control

Who can see and edit a table field is decided by Jira: the field configuration, the screens and the project permissions. Viewing a table needs no licence, because the data is yours. Editing asks a Forge function, which checks the licence on the server and fails closed in production.

Untrusted input

Everything typed or pasted into a table is untrusted input. Cells are checked against the type of their column, and the sizes are limited: 20 columns, 200 rows, 1,000 characters per cell, 300 characters per formula and about 30,000 characters per table. Formulas are read by a small arithmetic parser (numbers, column names in braces, + - * / %, parentheses, round, min, max, abs and sum) and are never run as code. Automated tests check that a formula cannot run code.

Logging

The app writes no logs of its own. Table content is never logged.

Encryption

Data in transit and at rest is protected by the Atlassian Forge platform. The app has no database or storage outside Forge.

Sub-processors

None besides Atlassian.

AI and language models

None. The app does not use Forge LLM and sends no content to any model.

Vulnerabilities and incidents

We fix vulnerabilities within the windows Atlassian requires of Marketplace apps (critical: 10 days, high: 4 weeks, medium: 12 weeks, low: 25 weeks) and tell Atlassian about security incidents within 48 hours. Dependencies are checked for known vulnerabilities before each release.

Report a vulnerability to support@karelialabs.com. Please include what you found, how to reproduce it and which app and version are affected, and give us a reasonable time to fix it before you publish details.

Deleting data

There is nothing of the app's own to delete. Tables are changed and deleted in Jira like any other field value. When Gridwright is uninstalled, fields of its type disappear from Jira. Atlassian states that if the app is reinstalled within 30 days, the fields reappear with their previous data.
