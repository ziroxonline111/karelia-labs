What you need

  • Jira Cloud (Jira, or Jira Service Management).
  • Gridwright installed on your site. Installing an app needs a Jira site administrator.
  • A Jira administrator to create the table fields and set up their columns.

Gridwright requests no permissions. A table is the value of its own field, and Jira hands it to the app when someone views or edits the field.

Add a table field in five steps

  1. As a Jira administrator, open the field settings of Jira (Work items, Fields) and choose Create new field. Choose the type Table grid (Gridwright) and name the field, for example Bill of materials.
  2. Open the field, then Contexts and default value, and choose Configure for the context. The Gridwright setup opens.
  3. Under Start from a template… choose a template, for example Bill of materials, and select Use template. Or build your own columns with Add column.
  4. Select Save configuration. The message says that issues in this context use these columns now.
  5. Add the field to the create, edit and view screens of your projects, and to transition screens if you want it there.

Columns

Every field context has its own columns, up to 20. Give each column a name and a type:

TypeWhat it holds
TextAny text, up to 1,000 characters
NumberA number with a set number of decimals and an optional prefix or suffix, such as $ or h
DateA date, picked from a calendar. Pasted dates can be written 2026-11-20 or 20.11.2026
Select listOne of a list of options, up to 50
CheckboxTicked or not
CalculatedA formula over other number columns, worked out for every row
  • Tick Required for cells that must be filled in, and Sum for number and calculated columns that should be added up.
  • Settings opens the details of a column: the options of a select list, the formula, the decimals, the prefix and the suffix.
  • Up, Down and Remove change the order and remove columns.
  • Under Rows, set Most rows per issue (up to 200) and choose Show a totals row for columns with Sum.
  • Preview shows two example rows with the current setup.

Problems are listed under Fix these before saving, and Save configuration stays unavailable until they are fixed. Existing values stay with their column when you rename or reorder columns.

Templates

Six templates fill in a whole setup that you can then change:

TemplateColumns
Bill of materialsPart, Qty, Unit price and Line total ({Qty} * {Unit price}), with totals
Cost breakdownCost item, Category, Estimate, Actual and Difference ({Actual} - {Estimate}), with totals
Test stepsStep, Expected result, Actual result and Status (Not run, Passed, Failed, Blocked)
Risk listRisk, Likelihood, Impact, Score ({Likelihood} * {Impact}) and Mitigation
Action itemsAction, Owner, Due and Done
Time estimateTask, Hours, Rate and Cost (round({Hours} * {Rate}, 2)), with totals

Calculated columns

Write the formula with the names of other number columns in braces:

{Qty} * {Unit price}
round({Hours} * {Rate}, 2)
max({Estimate}, {Actual}) - min({Estimate}, {Actual})
  • Operators: + - * / % and parentheses.
  • Functions: round(x) or round(x, digits), min, max, abs and sum.
  • A formula can use other calculated columns. A formula that depends on itself is refused.
  • An empty cell makes the result empty, except inside sum(), which counts it as 0. Division by zero gives an empty result.
  • A formula can have up to 300 characters. It is checked when you save the setup, so a typo never reaches an issue.

Formulas are read by a small calculator of their own and are never run as code.

Editing a table

On the issue, select the table to edit it, and save with Jira's own buttons. On the create screen and on transition screens the table is part of the form, and it is saved with the issue or the transition.

  • Add row adds a row and Remove removes one. Drag rows to change their order.
  • Numbers are read the way people type them: 1234.5, 1,234.5, 1 234,5 or $ 40.
  • A value that cannot be read stays in its cell and is marked, and the table is not saved until it is fixed.
  • Calculated cells and the totals row update as you type.
  • The line under the table shows how many rows there are and how many the field allows.

Paste from Excel

Select Paste from Excel… and paste rows copied from Excel, Google Sheets or a CSV file (tab, comma or semicolon separated).

  • When the first line names the columns, cells are matched to the columns by name, in any order. Otherwise they are taken in column order.
  • The preview says how many rows were found and how the columns were matched, and lists problems by line, for example a text in a number column.
  • Choose Add N rows to add the rows, or Replace all rows.

Copy as CSV

Copy as CSV… shows the table as CSV text. Select all, copy and paste it into a spreadsheet. It is text to copy, not a file download.

Lists, search and the portal

  • Issue lists, notifications and Jira's own CSV export show a short summary of the table, such as "4 rows · Qty: 38 · Line total: $46.12".
  • Search by the number of rows with JQL: "Bill of materials.rows" > 5.
  • Search for text in any cell with ~: "Bill of materials" ~ "bolt".
  • In the Jira Service Management portal, customers see table fields read-only.

Limits

  • Up to 20 columns per field context and 200 rows per table.
  • About 30,000 characters of data per table. Very long texts reach this limit before the row limit, and the app says so before saving.
  • 1,000 characters per cell, 50 options per select list and 300 characters per formula.
  • No user picker column in this version.
  • Table fields cannot be bulk edited, and customers cannot edit them in the portal.
  • Copy as CSV gives text to paste, not a file.
  • Without an active licence, tables stay visible but cannot be edited.

Permissions and data

Gridwright requests no permissions and stores nothing of its own. The rows are the value of the Jira field and the columns are the configuration of the field context, both kept by Jira. See Security and the Privacy Policy.
