What it does

Parts and quantities, test steps, costs per item, risks and owners are lists, not sentences. In Jira they often end up as sub-tasks, a table pasted into the description, or a panel that only appears after the issue exists. Gridwright makes the table a real Jira field: an administrator creates it in the field settings and puts it on the screens you choose, the Create screen included.

Each field context gets its own columns: text, numbers, dates, select lists, checkboxes and calculated columns with a totals row. People fill in the table while they create the issue, paste rows from a spreadsheet, and find issues by the contents of the table with JQL.

  • A field, not a workaround

    A custom field type that goes on create, edit and transition screens like any other field. Issue lists, notifications and Jira's CSV export show a short summary of the table.

  • Columns per field context

    Up to 20 columns: text, number, date, select list, checkbox and calculated. Mark columns as required or summed, and limit the rows per issue.

  • Calculated columns and totals

    Write {Qty} * {Unit price} once and every row calculates as you type, with a totals row. Formulas are checked when you save the setup and are never run as code.

  • Paste from Excel, copy as CSV

    Paste rows from Excel or Google Sheets. Columns are matched by the first line, and problems are listed by line before anything changes. Copy the table back out as CSV text.

  • Search with JQL

    Find issues by the number of rows, such as "Bill of materials".rows > 5, or by text in any cell.

  • Six starter templates

    Bill of materials, Cost breakdown, Test steps, Risk list, Action items and Time estimate fill in a whole column setup that you can change.

Built only on Atlassian Forge

Gridwright is built only on Atlassian Forge. Its manifest allows no outbound network access and has no remotes, no web triggers and no Connect modules. It makes no calls to outside servers, and your data stays in Atlassian: in Jira itself, as the value of the field. Its eligibility for Atlassian's Runs on Atlassian program has not been confirmed yet.

Good to know

  • A Jira administrator creates the table fields and sets up their columns, up to 20 per field context.
  • A table holds up to 200 rows and about 30,000 characters of data. Very long texts reach the character limit first, and the app says so before saving.
  • There is no user picker column in this version, so no account ids are stored.
  • Customers see table fields in the Jira Service Management portal, read-only. Table fields cannot be bulk edited.
  • Copy as CSV gives text to paste into a spreadsheet. It is not a file download.
  • Without an active licence, tables stay visible but cannot be edited.

Data and security

Gridwright requests no permissions and stores nothing of its own. A table is the value of its Jira field, kept by Jira, and the app makes no calls to outside servers. The security page lists what is stored, for how long and which permissions are needed. The privacy policy and the EULA are public.
