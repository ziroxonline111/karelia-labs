Response times

  • Errors that stop the spreadsheet from opening or saving: we aim to reply within 2 business days.
  • Other requests: we aim to reply within 5 business days.

These times apply during Monday to Friday, 09:00 to 17:00 Central European Time.

What to include

A good request lets us answer without asking questions first.

  • Your Statamic and PHP versions, and the addon version (php please support:details prints them all).
  • The collection, and the fieldtype of the column where the problem happens.
  • The message on the cell (hover it) or in the browser console, if there is one.
  • What you expected to happen, and what happened instead. A screenshot helps.
  • When it happened, with your time zone.

Please do not send passwords or confidential content. If we need an example, we will ask for it.

Common questions

A column is grey and cannot be edited.

Its fieldtype is shown read-only, such as Bard, Replicator, Grid or Table, or the field is set to read only in the blueprint, or it is not localizable and you are on a translation. Edit it on the entry page.

A cell turned red when I pasted.

The value cannot be right for that field, for example a word in a number field or a tag that does not exist. Hover the cell to see why. Red cells are never sent.

Save says a value is invalid.

The blueprint's validation rules refused it, exactly as the entry page would. Hover the cell for the message, fix it and save again. The other entries were saved.

Pasted entries or assets are not recognised.

Pasted relationship values must be IDs, or term slugs for fields with one taxonomy. Use the picker (Enter on the cell) to search by title.

An editor cannot see the spreadsheet.

Tick Use the spreadsheet for their role under Users, Roles. They also need view access to the collection. On Statamic Core there are no roles, so only the super admin uses it.

Not all entries are loaded.

One sheet loads up to 2,000 entries by default. Search, open a selection with Edit in Spreadsheet, or raise the limit in the config.

Security issues

If you believe you have found a vulnerability, do not post it publicly. Write to support@karelialabs.atlassian.net instead. The security page says what to include.
